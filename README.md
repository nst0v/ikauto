# ikauto.ru

Независимая статическая версия сайта `ikauto.ru`, пересобранная без Tilda. Изображения и шрифт хранятся локально. Видео RUTUBE загружаются только после согласия посетителя; ссылки на мессенджеры открываются по его явному действию.

## Запуск

```bash
npm install
npm run dev
```

Продакшен-сборка:

```bash
npm run build
npm run preview
```

Готовые файлы появятся в `dist/`.

## Формы

Все четыре формы по умолчанию отправляют JSON на встроенный `/api/lead.php`. Обработчик работает на PHP-хостинге, проверяет источник, согласие и поля, ограничивает частоту запросов и отправляет заявку на заданный в нём email. После настройки MAX он также передаёт заявку в один привязанный групповой чат. В MAX отображаются контакты, параметры заявки, сообщение и время получения; название формы, сведения о согласии и страница сохраняются в письме.

Чтобы вместо него использовать российскую CRM или свой API, скопируйте `.env.example` в `.env` и укажите:

```dotenv
VITE_FORM_ENDPOINT=https://example.com/api/leads
```

Endpoint должен принимать `POST` с JSON и отвечать JSON-объектом `{ "ok": true }` только после успешной передачи заявки. Он должен хранить данные на территории РФ и сохранять доказательство согласия (`personalDataConsent`, `consentVersion`, `consentAt`, форма и страница). При подключении нового обработчика нужно актуализировать Политику и настройки CSP в `public/.htaccess`.

В локальном `vite preview` PHP-код не исполняется. Полную отправку проверяйте на PHP-хостинге или через mock в Playwright.

## Уведомления в MAX

Нужны PHP 8.0 или новее, расширение cURL, HTTPS и возможность запускать PHP по расписанию. Токен используется только сервером: не добавляйте его в `VITE_*`, исходный JavaScript или Git. Vite не загружает серверные настройки из `.env` в PHP.

Если `max-bot.php` расположен отдельно от приведённой ниже структуры, задайте `MAX_LIBRARY_FILE` с абсолютным путём к `api/max.php` при каждом запуске CLI, включая cron.

1. Выполните `npm run build`. Разместите содержимое `dist/` в корне сайта с исполнением PHP. Отдельно загрузите `scripts/max-bot.php` за пределы корня сайта. Например:

   ```text
   /home/account/ikauto/
     scripts/max-bot.php
     ikauto-private/          # конфигурация и очередь, создаются при init
     public/                 # корень сайта: содержимое dist/
       api/lead.php
       api/max.php
       api/max-webhook.php
   ```

2. На сервере выполните:

   ```bash
   php /home/account/ikauto/scripts/max-bot.php init
   ```

   Введите токен в запросе скрипта. Он сохранится в `ikauto-private/max.php`; каталог должен оставаться вне корня сайта и быть доступен на запись пользователю PHP. Команда также создаёт секрет webhook и код привязки. Если конфигурация размещается в другом месте, задайте серверную переменную `MAX_CONFIG_FILE` с абсолютным путём. CLI и обработчики сайта должны использовать одну конфигурацию и один каталог состояния.

3. Проверьте токен и зарегистрируйте webhook:

   ```bash
   php /home/account/ikauto/scripts/max-bot.php status
   php /home/account/ikauto/scripts/max-bot.php subscribe https://ikauto.ru/api/max-webhook.php
   ```

   API MAX использует `https://platform-api2.max.ru`. Проверка TLS включена. Если хостингу нужен отдельный доверенный CA bundle, укажите его абсолютный путь в `MAX_CA_BUNDLE`; не отключайте проверку сертификата.

4. В настройках бота MAX разрешите добавление в групповые чаты. Создайте закрытую группу, добавьте бота и назначьте его администратором с правами чтения сообщений и отправки (`read_all_messages`, `write`). Добавьте в группу только Оператора и лиц, которым он разрешил обрабатывать заявки: все участники увидят поступающие заявки.

5. Получите команду привязки и отправьте её в созданную группу:

   ```bash
   php /home/account/ikauto/scripts/max-bot.php connect-command
   ```

   Бот ответит подтверждением. Команда `/connect <код>` работает только в групповом чате. После привязки другой чат не может заменить получателя. При удалении бота доставка приостанавливается и возобновляется после его добавления в ту же группу. Командой привязки в исходной группе также можно возобновить доставку.

6. Добавьте задание cron раз в минуту, используя пути вашего хостинга:

   ```cron
   * * * * * /usr/bin/php /home/account/ikauto/scripts/max-bot.php flush
   ```

   Контрольная отправка в привязанную группу:

   ```bash
   php /home/account/ikauto/scripts/max-bot.php test
   ```

Заявка для MAX сначала сохраняется в закрытой серверной очереди, затем отправляется в чат. При временной ошибке API файл остаётся в очереди для повторной попытки. До привязки чата заявки также накапливаются в очереди. Её обрабатывают cron, новые заявки и привязка чата; cron обеспечивает повторную отправку без посещений сайта. После доставки файл удаляется. Письмо отправляется независимо от доступности MAX. Форма получает успешный ответ, если письмо отправлено или заявка надёжно принята в очередь MAX; при отказе обоих способов возвращается ошибка.

Вместо конфигурационного файла можно задать серверные переменные `MAX_BOT_TOKEN`, `MAX_WEBHOOK_SECRET`, `MAX_CONNECT_CODE` и `MAX_STATE_DIR` (абсолютный путь к закрытому каталогу очереди и состояния). Необязательный `MAX_CHAT_ID` задаёт получателя заранее вместо команды привязки. Секрет webhook, код привязки и токен не должны попадать в публичные файлы. Для диагностики используйте `status`: он показывает бота, состояние привязки и число ожидающих заявок без вывода токена.

Официальная документация: [настройка групп](https://dev.max.ru/docs/chatbots/bots-coding/masterbot), [подписка webhook](https://dev.max.ru/docs-api/methods/POST/subscriptions/), [отправка сообщений](https://dev.max.ru/docs-api/methods/POST/messages/).

## Яндекс Метрика

На главной странице счётчик `114366595` запускается после согласия на аналитику. Для всех четырёх форм используется одна цель типа «Целевое событие» с условием «совпадает» и идентификатором `lead_success`. Сайт отправляет событие после ответа обработчика `{"ok": true}` с успешным HTTP-статусом.

## Индексирование в поиске

`public/robots.txt` разрешает обход страниц и ресурсов сайта, закрывает служебный каталог `/api/` и указывает адрес карты сайта: `https://ikauto.ru/sitemap.xml`. В `public/sitemap.xml` перечислены канонические HTTPS-адреса всех пяти страниц: главной и четырёх правовых документов. При добавлении или удалении страниц обновляйте карту сайта и их `rel="canonical"`.

Vite копирует оба файла в корень `dist/`. При публикации загружайте их вместе с остальной сборкой; по адресам `/robots.txt` и `/sitemap.xml` сервер должен возвращать HTTP 200. В карту включаются страницы с содержимым, без `/api/`, параметров отслеживания и якорей.

Владелец сайта должен добавить `https://ikauto.ru/` в [Яндекс Вебмастер](https://webmaster.yandex.ru/), подтвердить права, указать `https://ikauto.ru/sitemap.xml` в разделе файлов Sitemap и отправить главную на переобход. Эти действия требуют входа в аккаунт владельца. Фактическое присутствие проверяется в разделе «Индексирование → Страницы в поиске»; наличие robots.txt и Sitemap само по себе не гарантирует немедленного появления в выдаче. [Инструкция Яндекса](https://yandex.ru/support/webmaster/ru/site-indexing/page-in-search.html).

После публикации изменённой главной можно уведомить Яндекс через [IndexNow](https://yandex.ru/support/webmaster/ru/indexnow/reference): `npm run seo:notify`. Для других изменённых страниц передайте их HTTPS-адреса после `--`. Скрипт читает `ikauto-private/indexnow.json` с полями `key` и `keyLocation` либо переменные `INDEXNOW_KEY` и `INDEXNOW_KEY_LOCATION`, сначала проверяет опубликованный TXT-файл, затем отправляет уведомление. Ключ и `public/indexnow-*.txt` исключены из Git; Vite копирует локальный проверочный файл в сборку. При развёртывании из свежего клона восстановите этот файл из закрытых настроек или сохраните существующий файл на сервере. HTTP 200 означает принятие уведомления, HTTP 202 — принятие с ожидающей проверкой ключа; это не гарантия включения страницы в выдачу.

## Правовые страницы

- `/privacy.html` — политика обработки персональных данных;
- `/consent.html` — отдельное согласие на обработку;
- `/cookies.html` — cookie, Web Storage и RUTUBE;
- `/terms.html` — правовая информация и условия сайта.

В текущей редакции оператор указан как самозанятая (НПД) с ФИО, ИНН, городом, email и телефоном. При смене статуса или контактов эти данные нужно сразу обновить во всех правовых документах.
